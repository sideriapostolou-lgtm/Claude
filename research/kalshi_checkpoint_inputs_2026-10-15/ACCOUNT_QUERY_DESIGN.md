## Counterexamples the coverage planner must preserve

1. Old untracked `nc-speed-` RESTING order appears after startup with created_ts earlier than overlap: global resting must catch/cancel it and latch fatal before further sends, within existing full deadline.
2. Old untracked CANCELED/EXECUTED bot-prefix order appears outside recent/open filters: periodic first ALL audit must still detect it; startup-only-full fails.
3. Owner's resting bid entered >900s before a future window opens; net positions zero. Must mark foreign before first buy under existing opening-scan contract. Position-only screening misses paired/flat owner activity.
4. Old owner executed row and matching fill beside an unknown-ID bot intent, exact same terms or unreadable terms: must remain unattributed/uncertain. `_same_terms` is conservative; never call it owner-only and release the bot reservation. Different proved terms retain owner treatment.
5. Ambiguous create lands and fills completely between order1 and fills/order2; order ID appears only after fills. `order_found_after_fills` pauses until another fills pass; never resend create or clear reservation on a filtered absence.
6. Late/backdated fill for a terminal order outside min_ts, including already archived/settled window: full fills since start must catch and record/reopen/halt as the original. Fill-ID duplicate/conflict and actual fees must remain exact.
7. Old known terminal row changes remaining>0, filled count, price, size or identity between the two passes. Resting union catches some reopenings, but a canceled/executed count correction outside creation min_ts is the blocking counterexample for the narrowed second pass.
8. Cancellation occurs inside `_read` polling; delayed fill arrives despite ack, cancel fails or ID changes. Keep cancellation priority, cancel_failed/read generation ordering and all reservations until reconciled.
9. One incomplete status/recent/lookup page, repeated/missing cursor, rate429/auth error/timeout, malformed timestamps or unknown status: no completeness/prefix/absence/reset/fresh-account success. No automatic all-read retry can silently create orders or exceed bounded experiment resources.
